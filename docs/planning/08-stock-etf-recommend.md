## 1. 문제 정의 (Problem Reframing)

- **처음 요청**: "주식·ETF 추천을 구체화하고 싶다"
- **재정의(한 줄)**: 어드바이저가 **테마→종목→근거→비중** 흐름으로 추천을 받되, 종목별 **판단 근거**(차트·이동평균선·밸류에이션)와 **사후 검증**까지 확인해 *스스로 판단*할 수 있어야 한다.
- **핵심 문제 3종 (모두 채택)**:
  1. 근거 부재 — AI가 종목을 주지만 "왜"를 설명할 근거가 없음
  2. 판단 시간 — 종목마다 HTS·네이버를 따로 뒤져야 해 응대가 느림
  3. 검증 부재 — 과거 추천의 사후 성과·신뢰를 추적 못 함

## 3. MVP Scope

### Must (이번 버전)
| # | 기능 | 설명 |
|---|------|------|
| M1 | 추천 흐름(테마→종목→비중) | 테마 선택 → 종목 추천 → 종목별 비중 제안 (현 2-step 강화) |
| M2 | 종목 근거 패널 | 기준가 차트 + 이동평균선(5/20/60/120) + 밸류지표(PBR·PER·EPS·ROE·배당). **우측 사이드 패널** |
| M3 | 시그널·종합점수·스크리닝 | 골든/데드크로스·정배열 자동해석 + 종합점수 + 지표 필터(예: PBR<1 & 정배열) |
| M4 | 성과·검증 | 백테스트("1년 전 담았다면?")는 **추천 흐름 안**, 추천 사후성과 추적은 **별도 탭** |

### Won't (이번 버전 OUT, 다음 버전)
- AI 애널리스트 대화("왜?" 채팅)
- 카드뉴스 자동 생성
- 추천→수정 포트폴리오 원클릭 연결
- 고객 위험성향 필터

> 즉, 이번 버전은 **독립형 추천+근거+검증 엔진**. 고객 연동은 전부 다음 버전.

### ⚠️ 핵심 의존성
- **종목·시장 해석 방식(시그널/종합점수 산정 로직)은 사용자가 별도 제공할 자료를 분석해 장착**한다. 자료 입수 전까지 점수/시그널 로직은 placeholder. (자료 대기)

## 4. 화면 구조

```
[탭] 추천            [탭] 성과·검증(사후성과)
 ├ Step1 테마 분석 (테마 목록 + 바스켓 + 테마 근거)
 ├ Step2 종목 추천  (종목 리스트 + 스크리닝 필터)
 │    └ 행 클릭 → [우측 사이드 패널] 차트+이평선+밸류지표+시그널+종합점수 + 백테스트
 └ Step3 비중 제안  (종목별 % 배분)
```
- 흐름: 테마 → 종목(+우측 근거 패널) → 비중
- 성과 추적은 별도 탭

## 5. 데이터 아키텍처 (사용자 제공 — 핵심)

> 원칙: **단일 소스 금지. 데이터 종류별 주력+백업.** 이동평균선은 수집이 아니라 **종가로 계산**.

| 필요 데이터 | 주력 | 백업 | 정식 | 비고 |
|------------|------|------|------|------|
| 일봉 OHLCV(이평선 계산용) | **KIS 기간별시세(수정주가)** | 네이버 차트 API | 정식 | 수정주가로 통일(액면분할·증자 보정) |
| 날짜별 기준가(수정주가) | KIS(수정주가 옵션) | Yahoo | 정식 | |
| EPS·PER·PBR·배당 | 네이버 종목 API | KIS 주식기본조회 | 비공식/정식 | v1은 후행 EPS로 충분 |
| 재무제표(기업분석) | **DART OpenAPI** | 네이버 재무 | 정식·무료 | 추가 연동 필요 |
| 공시 | **DART 공시검색(list.json)** | — | 정식·무료 | 이벤트=신호로도 활용 |
| 관련 기사 | **네이버 검색 OpenAPI(뉴스)** | — | 정식·무료 | 종목↔테마 공출현 정량화 |
| 테마-종목 매핑 | ETF 구성종목 역설계 + 네이버 테마 | 뉴스 공출현 | 스크래핑 | |
| 미국 ETF·매크로 | Yahoo | — | — | 한국 중소형주엔 부적합 |

**추가로 붙일 것**: DART(재무·공시) + 네이버 검색 API(뉴스). 시세 신뢰도 위해 KIS 수정주가를 주력으로.

### 파이프라인
```
[일배치]
 KIS(수정주가 OHLCV) ┐
 네이버(지표·차트백업)┼→ 종목 DB → 이평선·신호 계산 → 테마/종목 스코어
 DART(재무·공시) ────┤
 네이버검색(뉴스) ───┤
 ETF·테마(매핑) ─────┘
 Yahoo(미국 ETF·매크로)

[웹 프론트] = DB 읽기 전용 (테마 랭킹 → 종목 드릴다운 → 차트·재무·뉴스·공시)
```
- 과거 전체: KIS 수정주가로 1회 백필 → 매일 종가만 증분
- 5/20/60/120 이평선·골든크로스·이격도는 종가 시계열에서 코드 계산

### 4대 함정 (구현 시 필수 대응)
1. **수정주가 일관성** — 시세·신호는 한 소스(KIS 수정주가)로 통일 (소스 혼용 금지)
2. **종목 마스터** — 전종목 코드·종목명·시장구분 리스트(KRX/KIS) 주기 갱신(상장/폐지)
3. **영업일 캘린더** — 휴장일 처리, 거래일 기준 이평선 계산
4. **레이트리밋·토큰** — KIS 토큰 1일 1회 발급 + 초당 제한, 네이버 검색 일일 쿼터 → 배치 sleep/큐

## 6. 기술 방향 (초안)
- 백엔드: 일배치 수집기(KIS/DART/네이버) → 종목 DB(PostgreSQL) 적재 → 지표·신호·스코어 계산. 웹 API는 DB 읽기 전용.
- 프론트: 기존 stock-recommend 2-step 확장 + 우측 근거 사이드패널(차트=recharts/경량 캔들), 성과 별도 탭.
- (기존 스택: Next.js + FastAPI + PostgreSQL 재사용)
