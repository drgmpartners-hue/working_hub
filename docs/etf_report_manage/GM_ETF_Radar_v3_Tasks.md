# GM ETF Radar — v3 태스크 (이메일 발송 프로그램 · F4)

- 버전: v3.0 / 작성일: 2026-07-29
- 근거: [PRD v0.9](./GM_ETF_Radar_PRD_v0.9.md) §F3-4·F4, [Workflow v0.9](./GM_ETF_Radar_Workflow_v0.9.md) §W2(분기)·W4, [v2 Tasks](./GM_ETF_Radar_v2_Tasks.md)
- 범위: **3차 = 추적 결과를 이메일로 배포** — 일일 다이제스트 + 🔴 즉시 알림(G3 게이트) + 수신 그룹·구독 관리 + 대응 기록 루프
- 전제: v2(추적검증) 완료 — 일일 스캔 결과·`signal_events`·🔴 발동 이벤트 존재
- 규약: `[BE]` 백엔드 · `[FE]` 프론트 · `[AI]` 문구/프롬프트 · `[DATA]` 스키마 · `[QA]` 검증

> 컴플라이언스 고정: 모든 발송 문구는 "매도 권고"가 아니라 **"사전 정의 신호가 관측됨"** 형식(템플릿 레벨 강제). 면책 문구 필수. 매도 코멘트는 G3 승인분만.

## Phase 0 — 발송 데이터 모델 & 수신 그룹

### P0-1 [DATA] 구독·수신 스키마
- `subscribers`: id, role(ADMIN|ADVISOR|CUSTOMER), name, email, active
- `subscriptions`: subscriber_id, scope(ALL|THEME), theme? — 구독 테마만 수신
- `dispatch_log`: id, kind(DAILY_DIGEST|IMMEDIATE), subscriber_id, signal_id?, sent_at, status(SENT|FAILED|HELD), template_version
- **deps**: v2 완료 · **DoD**: 마이그레이션, 수신 그룹(관리자/자문사/고객) 구분

### P0-2 [DATA] G3 게이트·대응 기록 스키마
- `alert_reviews`: signal_event_id, decision(APPROVE|FALSE_POSITIVE|AUTO_SENT|HOLD), admin_comment?, reviewed_by?, decided_at
- **deps**: P0-1 · **DoD**: 🔴 이벤트별 관리자 처리 이력 저장 가능

## Phase 1 — 이메일 템플릿 (고정 규격)

### P1-1 [BE] 템플릿 엔진 (인라인 스타일·table 레이아웃)
- 이메일 제약: 인라인 스타일 + `<table>` 레이아웃만(외부 CSS·flex 금지), 다크모드 대비 색상 고정
- **deps**: 없음 · **DoD**: 렌더 → 주요 메일 클라이언트에서 레이아웃 유지

### P1-2 [AI/BE] 일일 다이제스트 템플릿
- 구성: ① 헤더(날짜·전체 요약 1줄) ② 변경 신호 테이블(상단 강조) ③ 전체 신호등 현황표(상태|테마|신호|오늘 관측값·근거|대응기준). 변경 없으면 "이상 없음" 1줄 + 현황표
- **deps**: P1-1 · **DoD**: `email_template_daily_digest.html` 규격 산출

### P1-3 [AI/BE] 즉시 알림 템플릿 (고정 문구)
- 고정: "『[리포트명]』에서 사전 정의된 신호 [신호명]이 관측되었습니다. 근거: [링크]. 리포트의 대응 기준: [축소/재검토]. 본 알림은 정보 제공이며 투자 판단은 투자자 본인에게 있습니다."
- **deps**: P1-1 · **DoD**: 매도 지시 표현 배제 검증(문구 락)

## Phase 2 — 일일 다이제스트 발송

### P2-1 [BE] 스캔 결과 → 다이제스트 조립
- v2 일일 스캔(P4-1) 완료 훅 → 변경 신호·현황표 데이터 조립
- **deps**: v2 P4-1, P1-2 · **DoD**: 당일 스캔 결과로 다이제스트 본문 생성

### P2-2 [BE] 수신 그룹별 발송 + 로그
- 관리자(전체)/자문사(담당 고객 테마)/고객(구독 테마만) 필터링 발송, 기존 이메일 인프라 재사용, `dispatch_log` 기록
- 변경 없음 = "이상 없음" 1줄(또는 주간 모아보기 옵션)
- **deps**: P2-1, P0-1 · **DoD**: 그룹별 발송 성공률 로깅, 발송 실패 재시도

## Phase 3 — 즉시 알림 + G3 게이트

### P3-1 [BE] 🔴 발동 이벤트 후크
- v2 집계 엔진 🔴 신규 발동 → 관리자 즉시 알림(내부) + G3 대기 큐 적재
- **deps**: v2 P3-2 · **DoD**: 🔴 발동 시 관리자 알림·큐 적재

### P3-2 [FE] G3 알림 확인 화면 (관리자)
- 선택: a) **승인+코멘트** → 고객 발송(중립 템플릿+관리자 코멘트) b) **오탐 마킹** → 발송 안 함 + 프롬프트 개선 큐 c) **무응답 N시간** → 설정에 따라 중립 문구 자동 발송 or 보류
- **deps**: P3-1, P0-2 · **DoD**: 3개 결정 경로 동작, 결정 이력 저장

### P3-3 [BE] G3 결정 → 고객 발송 실행
- 승인 시 즉시 알림 템플릿(P1-3)으로 수신 그룹 발송, `dispatch_log`(IMMEDIATE) 기록
- 무응답 자동 발송 스케줄(설정값)
- **deps**: P3-2 · **DoD**: 승인/자동 경로 모두 발송·로그

---

## Phase 4 — 배포/구독 관리 화면

### P4-1 [FE] 수신자·구독 관리 (관리자)
- 구독자(관리자/자문사/고객) CRUD, 구독 테마 지정, 발송 on/off
- **deps**: P0-1 · **DoD**: 구독자·구독 테마 관리

### P4-2 [FE] 발송 이력·현황
- `dispatch_log` 조회(일자·유형·수신자·상태), 발송 성공률 지표
- **deps**: P2·P3 · **DoD**: 발송 이력 필터·성공률 표시

### P4-3 [FE] (선택) 고객용 알림 이력 뷰
- 고객이 자기 구독 테마의 알림 이력·최신 리포트 링크 열람(최소 뷰). 규모에 따라 후속 가능
- **deps**: P4-1 · **DoD**: 고객 알림 이력 열람(스코프 제한)

---

## Phase 5 — 대응 기록 루프 (운영 표준 W4)

### P5-1 [BE] 대응 결정 기록 → 후속 안내
- 🔴 발송 후 관리자 대응 결정(축소 권고/관찰 유지/오탐) 기록 → **다음 다이제스트에 "후속 안내"로 포함**
- **deps**: P3, P2 · **DoD**: 대응 기록이 익일 다이제스트에 반영

### P5-2 [BE] 오탐 → 프롬프트 개선 큐 (주간 리뷰)
- 오탐 마킹 건 집계 → 판정 프롬프트/임계값 수정 후보 큐, 프롬프트 버전 업 워크플로
- **deps**: v2 P5-3, P3-2 · **DoD**: 주간 오탐 리포트 + 개선 큐 생성
