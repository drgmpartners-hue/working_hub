# Workflow — GM ETF Radar (리포트 생성 · 시그널 추적 · 알림 대응)

- 버전: v0.9 / 작성일: 2026-07-29 / PRD v0.9와 짝을 이루는 문서
- 표기: [자동] = 시스템 실행, [G] = 사람 게이트, → = 순차, ⇉ = 병렬

---

## W1. 리포트 생성 워크플로 (F1·F2)

```
[트리거] 관리자 수동 실행 또는 월간 스케줄
   │
   ▼
[자동] S1 시장 리서치 & 롱리스트
   · Claude API + 웹검색 (국내/미국 전망, ETF 트렌드 — 쿼리에 현재 연·반기 포함)
   · 출력(JSON): macro_summary, themes[≈10×2시장]{논리, 출처URL, 대표ETF, 태그: 실적형|전환형|기대형}
   ▼
[자동] S2 축출 라운드
   · 규칙: 기대형 = 축출 1순위, 남기려면 별도 논거 필수
   · 출력: culled[]{테마, 사유(구체), 재진입조건}, survivors[]
   ▼
[자동] S3 밸류에이션 + 레드팀
   · 테마별: 컨센서스 반영도 / bear case×2 / 조기경고지표 / 판정(유지·축소·축출)
   · ★조기경고지표는 이후 시그널 레지스트리의 원천이 되므로 "측정 가능한 형태"로 쓰도록 프롬프트 강제
     (나쁨: "지정학 완화" / 좋음: "러-우 휴전 합의 보도" — 관측 가능해야 함)
   ▼
[자동] S4 최종 테마 확정안 (3축 순위 + 상관관계 점검 + 이탈조건 초안)
   ▼
┏━[G1] 관리자 검토 게이트 ━━━━━━━━━━━━━━━━━━━━━┓
┃ 화면: 최종 테마안 + 축출 사유 + 레드팀 전문                  ┃
┃ 선택: 승인 / 테마 되살리기·수정(사유 입력) / S1부터 재실행     ┃
┗━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━┛
   ▼
[자동] S5 상품 실사
   · 국장 테마: 국내 ETF 3개 / 미장 테마: 미국판 3 + 국내판 3
   · 필수 필드: 수익률(YTD·1Y·3Y, 기준일 필수), 상위10~15종목·비중, 배당, 보수, AUM
   · 데이터 미확보 필드 = "확인 불가" (추정 금지)
   ▼
[자동] S6 리포트 렌더링
   · JSON → 리포트 MD → Dr.GM 규격 HTML → PDF (weasyprint 엔진 재사용)
   · ★디자인 규격: gm-ppt-builder 스킬의 Dr.GM 마스터 규격을 단일 원천(SSOT)으로 따른다
     — 컬러: 딥네이비 #0B1F3A / 보조네이비 #16223A / 아이보리 #FBFAF6 / 라이트아이보리 #F7F4EC
       골드 #C9A24A / 딥골드 #A5821F / 라이트골드 #E6CA84 / 라인베이지 #E4E0D2 / 메타그레이 #8089A0
     — 원칙: 골드는 강조 전용(넓은 면색 금지), 밝은 면=컬러 텍스트·네이비 면=흰색 텍스트, 표지 로고(화이트) 포함
     — 구현 시 gm-ppt-builder/SKILL.md를 개발 저장소에 design-reference로 복사해 두고 참조할 것
   · 직전 리포트 존재 시: 변경 요약 섹션 자동 생성 (테마 진입/이탈/순위 변동)
   ▼
┏━[G2] 발행 승인 게이트 ━━━━━━━━━━━━━━━━━━━━━━┓
┃ 승인 시 3가지가 동시 발생:                                  ┃
┃  ① 고객·자문사 배포 (웹 게시 + 이메일)                      ┃
┃  ② 이탈 조건 → 시그널 레지스트리 자동 등록 (W3)             ┃
┃  ③ 직전 리포트의 신호 중 승계되지 않은 것 만료 처리           ┃
┗━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━┛
```

## W2. 일일 시그널 추적 워크플로 (F3) — 시스템의 심장

```
[트리거] 매 영업일 새벽 (예: 07:00 KST, 미장 마감 후)
   │
   ├─⇉ [자동] QUANT 수집기
   │     FRED(美10년물)·ECOS(기준금리)·KRX(ETF가격·낙폭)·환율 API 호출
   │     → 규칙 판정: 임계값 충족? + 2영업일 연속? → 🟢/🟡/🔴
   │
   ├─⇉ [자동] NEWS 수집기 (LLM 배치 — 테마당 1회 호출)
   │     테마별 웹검색 스캔 → 구조화 출력:
   │     {signal_id, hit: yes|watch|no, evidence[], source_urls[], confidence}
   │     → 규칙: 출처 2개 이상 & confidence 기준 통과 시만 🔴 후보
   │     → 프록시 신호는 최대 🟡 (자동 🔴 금지)
   │
   ├─⇉ [자동] DISCLOSURE 수집기
   │     DART OpenAPI 키워드 필터(수주 취소·계약 해지·정정) → 후보만 LLM 판정
   │
   └─⇉ [자동] EARNINGS 수집기 (실적 시즌만 활성)
         실적 캘린더 매칭 → 발표문·기사 LLM 요약 → capex/수주 가이던스 방향 판정
   │
   ▼
[자동] 집계 엔진
   · 신호 상태 갱신 + 이력 저장(근거 스냅샷 포함)
   · 테마 등급 = 소속 신호 최고 등급 / "지정학 묶음" 신호는 묶음 전체 전파
   · 수집기 실패 = 해당 신호 "확인 불가" 표기 (침묵 금지)
   ▼
분기: 🔴 신규 발동 있음? ──아니오──▶ [자동] 일일 다이제스트 발송
   │                                 · 형식: HTML 테이블 이메일 (첨부 템플릿
   │                                   email_template_daily_digest.html 참조)
   │                                 · 구성: ① 헤더(날짜·전체 요약 1줄)
   │                                   ② 변경 신호 테이블(상단 강조)
   │                                   ③ 전체 신호등 현황 테이블
   │                                   (상태|테마|신호|오늘 관측값·근거|대응 기준)
   │                                 · 이메일 제약: 인라인 스타일 + <table> 레이아웃만
   │                                   사용(외부 CSS·플렉스 금지), 다크모드 대비 색상 고정
   │                                 · 변경 없으면 "이상 없음" 1줄 + 현황표만
   예
   ▼
┏━[G3] 🔴 알림 확인 게이트 (관리자) ━━━━━━━━━━━━━━━┓
┃ 즉시 관리자 알림 → 선택:                                    ┃
┃  a) 승인+코멘트: 고객 발송 (중립 템플릿 + 관리자 코멘트)      ┃
┃  b) 오탐 마킹: 발송 안 함 + 판정 프롬프트 개선 큐에 기록       ┃
┃  c) 무응답 N시간: 설정에 따라 중립 문구 자동 발송 or 보류       ┃
┃ ※ 발송 문구는 "사전 정의 신호 관측" 고정 템플릿 (매도 지시 금지) ┃
┗━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━┛
```

## W3. 시그널 등록·생명주기 워크플로

```
리포트 G2 승인
   ▼
[자동] 이탈 조건 파싱 → 신호 후보 생성 (LLM: 자연어 조건 → Signal 스키마 변환)
   · 유형 자동 분류 (QUANT/NEWS/DISCLOSURE/EARNINGS)
   · ★기존 LIBRARY(공통 상비 신호)와 동일 대상·지표면 신규 생성 대신 링크(ReportSignalLink) 생성
     — 애매하면 REPORT 신호로 생성 후 검수 화면에 병합 제안 표시 (PRD F3-1 참조)
   · QUANT는 소스 매핑 시도 → 매핑 실패 시 "프록시 필요" 플래그
   ▼
[G2 연장] 관리자 최종 확인 화면 — 신호 목록·임계값·프록시 여부 검수 후 활성화
   ▼
활성 (일일 추적 대상) ── 리포트 갱신 시 ──▶ 승계 or 만료
                     └─ 관리자 수동: 추가·수정·일시정지 가능
```

- 만료 규칙: 신호는 소속 리포트의 유효기간(기본: 다음 리포트 발행 시)까지만 활성. 승계되는 테마의 신호는 새 리포트 기준으로 재검수.

## W4. 알림 이후 대응 워크플로 (운영 표준)

```
🔴 발송됨
   ▼
관리자: 대응 결정 기록 (축소 권고 코멘트 발행 / 관찰 유지 / 오탐)
   ▼
[자동] 대응 기록이 다음 다이제스트에 "후속 안내"로 포함
   ▼
주간 리뷰: 오탐 마킹 건 → 판정 프롬프트/임계값 수정 → 프롬프트 버전 업
```

## 구현 참고 (기술 스택 제안 — 강제 아님)

- 스케줄러: 기존 사이트 인프라의 cron / Make 시나리오 (이미 사용 중인 Make로 W2 트리거·이메일 발송 구성 가능)
- LLM: Claude API (web_search tool). S1~S5는 messages 체인, 일일 스캔은 테마당 1콜 배치
- 데이터: FRED·ECOS·DART OpenAPI(무료 키), KRX 정보데이터시스템, 실적 캘린더(공개 소스)
- 저장: 기존 사이트 DB에 reports / signals / signal_events / dispatch_log 4테이블이면 MVP 충분
- 이메일: 기존 발송 인프라 재사용, 템플릿 2종(다이제스트/즉시 알림)

## MVP 최소 경로 (PRD 7장과 동일 — 다시 강조)

1주차에 만들 것은 W2 하나다: 현행 리포트 8개 테마의 이탈 조건 ~12개를 **수동으로** 레지스트리에 넣고(W3 자동화 생략), QUANT 3~4개 + NEWS 배치 스캔 1개짜리 파이프라인으로 매일 아침 관리자 1인에게 다이제스트를 보내는 것. 이게 돌아가면 나머지는 전부 이 위에 얹는 확장이다.
