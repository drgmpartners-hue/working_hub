# PRD — 테마 ETF 리서치 & 시그널 추적 시스템 (가칭 "GM ETF Radar")

- 버전: v0.9 (초안) / 작성일: 2026-07-29
- 작성: Claude (Dr.GM 요구사항 기반) / 오너: Dr.GM (골드마운틴파트너스 기획총괄)
- 배포 형태: **기존 웹사이트의 추가 기능 모듈** (신규 독립 서비스 아님)

---

## 1. 배경과 문제 정의

검증된 6단계 게이트 워크플로(etf-theme-selector 스킬: 시장 리서치 → 축출 → 밸류에이션·레드팀 → 테마 확정 → 상품 실사 → 리포트)로 테마 ETF 추천 리포트를 생산할 수 있게 됐다. 그러나 리포트는 **발행 시점의 스냅샷**이다. 실제 투자자에게 더 중요한 것은 "언제 나와야 하는가"인데, 리포트에 정의된 이탈 조건(매도 신호)을 사람이 매일 수동으로 확인하는 것은 불가능하다.

**해결하려는 문제**: ① 리포트 생산의 반복 가능성(사람 개입 최소화 + 품질 유지) ② 발행된 리포트의 이탈 조건을 **매일 자동 추적**하고 신호 발생 시 이메일로 알리는 사후 관리 ③ 이 전체를 고객·자문사에 배포 가능한 형태로 제공.

## 2. 사용자와 배포 구조 (B2B2C)

| 역할 | 설명 | 주요 행동 |
|---|---|---|
| 관리자 (Dr.GM 팀) | 시스템 운영 주체 | 리포트 생성 실행, 게이트 승인, 시그널 레지스트리 관리, 🔴알림 검토 |
| 자문사/FP | 배포 파트너 | 고객에게 리포트 전달, 추적 대시보드 열람 |
| 최종 고객 | 리포트·알림 수신자 | 리포트 열람, 일일/주간 시그널 이메일 수신 |

## 3. 컴플라이언스 전제 (설계 원칙에 반영)

- 본 시스템의 모든 출력은 **정보 제공**이며 투자자문·매매 지시가 아니다. 모든 리포트·이메일에 면책 문구 고정 삽입.
- 시그널 알림 문구는 "매도 권고"가 아니라 **"리포트에서 사전 정의한 신호가 관측됨"** 형식을 강제한다 (템플릿 레벨에서 고정).
- 매도 판단이 담긴 코멘트는 관리자 승인 게이트를 통과한 경우에만 발송 가능.
- 유사투자자문/투자자문업 등록 요건 해당 여부는 배포 전 별도 법률 검토 (오너 책임 — 본 PRD 범위 외).

## 4. 기능 요구사항

### F1. 리포트 생성 모듈 (반자동, 게이트 2개)

6단계 스킬 워크플로를 서버 파이프라인으로 이식하되, 사람 확인은 2개 게이트로 압축한다.

- 자동 실행 구간: STAGE 1(시장 리서치·롱리스트) → STAGE 2(축출) → STAGE 3(밸류에이션·레드팀) → STAGE 4(테마 확정안)
- **게이트 G1 (관리자)**: STAGE 4 결과 검토 화면 — 최종 테마안 + 축출 사유 + 레드팀 결과를 승인/수정/재실행. *근거: 축출·레드팀은 판단의 품질을 좌우하는 지점이라 사람 검증 가치가 가장 높음*
- 자동 실행 구간: STAGE 5(상품 실사) → STAGE 6(리포트 초안 + PDF 렌더링)
- **게이트 G2 (관리자)**: 발행 승인 — 승인 시 ① 고객 배포 ② 리포트의 이탈 조건이 시그널 레지스트리에 자동 등록(F3 연동)

> ### ⚠️ 필수 요구사항 R-CORE-1 — 리포트 발행 = 시그널 자동 등록 (구현 누락 금지)
> **G2 발행 승인은 반드시 시그널 레지스트리 등록을 트리거해야 하며, 이 둘은 하나의 트랜잭션으로 취급한다.**
> 등록이 실패하면 발행도 실패로 처리(롤백)한다 — "리포트는 나갔는데 추적은 안 되는" 상태가 이 시스템의 최악의 장애 모드이기 때문이다.
> 이 연동이 없으면 본 시스템은 '리포트 생성기'로 퇴화하며, 추적조사(F3)라는 핵심 가치가 사라진다.
> 수동 등록은 예외 경로(관리자 추가·수정)로만 존재하고, 기본 경로는 언제나 자동 등록이다.
> 검수 기준: G2 승인 직후 해당 리포트의 모든 이탈 조건이 레지스트리에 `report_id`로 연결되어 조회 가능해야 하며,
> 다음 영업일 다이제스트에 신규 신호로 나타나야 한다. (QA 시나리오에 포함할 것)
- LLM 엔진: Claude API (web_search tool 포함). 각 STAGE는 구조화된 JSON 산출물을 내고 다음 STAGE의 입력이 된다 (스킬의 문서 규격을 JSON 스키마로 변환).
- PDF: 기존 Dr.GM 규격 HTML→PDF 엔진(weasyprint, 딥네이비·아이보리·골드) 재사용.

### F2. 정기 리포트 스케줄러

- 월간(설정 가능) 자동 트리거로 F1 파이프라인 실행 → G1/G2 승인 큐에 적재 → 관리자 승인 후 배포.
- 재실행 시 직전 리포트와의 **차이(테마 진입/이탈, 순위 변동)를 자동 비교**해 "변경 요약" 섹션 생성.

### F3. 시그널 추적조사 모듈 (핵심 신규 기능)

#### F3-1. 시그널 레지스트리 (데이터 모델)

모든 이탈 조건을 구조화 레코드로 관리. **리포트 발행(G2) 시 자동 등록되는 것이 기본 경로**이며(R-CORE-1), 관리자 수동 추가·수정은 예외 경로다.

```
Signal {
  id, report_id, theme, etf_codes[],
  scope: REPORT | LIBRARY,                       // ★ REPORT: 특정 리포트 파생 / LIBRARY: 공통 상비 신호
  type: QUANT | NEWS | DISCLOSURE | EARNINGS,   // 4유형
  name: "미 10년물 금리 급등",
  source: { kind: "FRED", key: "DGS10" } | { kind: "news_scan", query_hints: [...] } | ...,
  rule: { threshold: ">= 5.0%", window: "5d" }   // QUANT: 코드 판정
      | { prompt_id: "geopolitics_detente_v2" }, // NEWS 등: LLM 판정 프롬프트 참조
  frequency: DAILY | WEEKLY | MONTHLY | EARNINGS_SEASON,
  action_on_trigger: "축소" | "재검토" | "지정학 묶음 전체 축소",
  status: GREEN | YELLOW | RED, status_history[],
  proxy_note: "클락슨 원본 유료 → 언론 인용 보도로 추적"  // 프록시 사용 시 명시
}
ReportSignalLink { report_id, signal_id, action_on_trigger_override? }  // LIBRARY 신호 ↔ 리포트 연결
```

**scope 구분과 공통 신호 라이브러리 (LIBRARY).** 신호는 두 부류로 나뉜다.
- `REPORT` (리포트 파생 신호): 특정 테마에만 붙는 신호 (예: 신조선가 지수 하락, 특대형 변압기 수출). 소속 리포트와 생명주기를 같이한다 — 리포트 갱신 시 승계 또는 만료.
- `LIBRARY` (공통 상비 신호): 어떤 리포트가 나와도 반복 등장하는 신호 (예: 미 10년물 금리, 한은 기준금리, 지정학 데탕트, 빅테크 capex 가이던스). **한 번만 정의하고 각 리포트가 ReportSignalLink로 참조만 한다.** 리포트가 만료돼도 라이브러리 신호 자체는 삭제되지 않으며, 연결이 모두 끊긴 신호만 휴면 처리한다.
- LIBRARY로 설계하는 이유: ① 판정 이력이 리포트를 넘어 누적되어 오탐 개선 루프의 데이터가 됨 ② 임계값·판정 프롬프트를 한 곳에서만 관리 ③ 여러 테마에 걸친 "묶음 전파"(지정학 신호 → 방산·조선 동시 적용)가 자연스럽게 구현됨.
- 자동 등록(W3) 시 분류 규칙: 파싱된 이탈 조건이 기존 LIBRARY 신호와 동일 대상·동일 지표면 신규 생성이 아니라 **링크 생성**으로 처리한다 (중복 신호 방지). 동일성 판단이 애매하면 신규 REPORT 신호로 만들고 관리자 검수 화면에서 병합 제안을 표시한다.

**동적 목록 원칙**: 다이제스트에 표시되는 신호 개수·구성은 고정이 아니라 "현재 활성 리포트에 연결된 신호 전체"다. 테마가 바뀌면 신호도 바뀐다.

#### F3-2. 유형별 수집기 (다양성 극복의 핵심 설계)

| 유형 | 예시 신호 | 수집 방법 | 판정 주체 |
|---|---|---|---|
| QUANT (정량지표) | 미 10년물, 기준금리, ETF 가격·낙폭, 환율 | FRED·ECOS·KRX 등 공개 API, 일 1회 | **코드** (임계값 규칙) |
| NEWS (뉴스이벤트) | 종전 협상 급진전, 데이터센터 규제 확산, 신조선가 하락 보도 | LLM + 웹 검색: 테마별 일일 스캔 | **LLM** (구조화 판정) |
| DISCLOSURE (공시) | 대형 수주 취소·계약 해지 | DART OpenAPI 키워드 필터 → 후보만 LLM 판정 | 코드 필터 + LLM |
| EARNINGS (실적·가이던스) | 빅테크 capex 가이던스, 수주 가이던스 | 실적 캘린더 기반 시즌 활성화, 발표문 LLM 요약·판정 | LLM |

- **접근 불가 데이터의 프록시 원칙**: 원천이 유료/비공개인 신호(예: 클락슨 신조선가 지수)는 "그 수치를 인용한 언론 보도"를 NEWS형으로 추적하고, `proxy_note`에 한계를 명시한다. 프록시 신호는 단독으로 🔴 발동 불가(YELLOW까지만) — 관리자 확인 후 RED 전환.
- 신규 신호 유형이 나와도 **4유형 중 하나로 귀속시키는 것을 원칙**으로 하고, 안 되면 유형 추가가 아니라 "수동 확인 목록"으로 분리한다 (유형 폭발 방지).

#### F3-3. 판정·집계 체계

- 신호 상태 3단계: 🟢 관찰(정상) / 🟡 주의(임계 근접 또는 단일 출처 포착) / 🔴 발동(규칙 충족)
- **🔴 발동 요건 (오탐 통제)**: ① QUANT — 임계값 충족 + 2영업일 연속 유지(원데이 스파이크 배제) ② NEWS/DISCLOSURE — 독립 출처 2개 이상 + LLM 확신도 기준 통과 + 근거 링크 필수 ③ 프록시 신호 — 자동 🔴 불가
- 테마 레벨 집계: 소속 신호들의 최고 등급 = 테마 등급. "지정학 묶음"처럼 여러 테마에 걸린 신호는 발동 시 묶음 전체에 전파.
- 모든 판정은 근거(수치 스냅샷 또는 기사 링크)와 함께 이력 저장 — 감사 추적 가능해야 함.

#### F3-4. 알림·이메일 규격

- **일일 다이제스트** (매 영업일 아침): 변경된 신호만 요약 + 테마별 신호등 현황표. 변경 없으면 "이상 없음" 1줄 (또는 주간 모아보기 옵션).
- **즉시 알림**: 🔴 발동 시. 단, 고객 발송 전 **게이트 G3(관리자 확인)** 경유가 기본값 — 관리자가 N시간 내 미처리 시 "신호 관측" 중립 문구로 자동 발송할지는 설정값으로.
- 문구 템플릿(고정): "『[리포트명]』에서 사전 정의된 신호 [신호명]이 관측되었습니다. 근거: [링크]. 리포트의 대응 기준: [축소/재검토]. 본 알림은 정보 제공이며 투자 판단은 투자자 본인에게 있습니다."
- 수신 그룹: 관리자(전체) / 자문사(담당 고객 테마) / 고객(구독 테마만).

### F4. 열람 화면 (기존 웹사이트 내 페이지)

- 고객용: 최신 리포트 뷰어(PDF/웹), 내 구독 테마의 신호등 대시보드, 알림 이력
- 관리자용: 승인 큐(G1/G2/G3), 시그널 레지스트리 CRUD, 판정 이력·오탐 마킹(프롬프트 개선 루프용)

## 5. 비기능 요구사항

- **비용 상한**: LLM 일일 스캔은 테마당 1회 배치(신호별 개별 호출 금지), 월 API 예산 상한과 사용량 모니터링 필수
- **재현성**: 모든 LLM 판정에 프롬프트 버전ID 기록. 판정 프롬프트는 코드와 분리된 레지스트리로 관리
- **장애 격리**: 수집기 1종 장애가 전체 파이프라인을 막지 않도록 병렬·독립 실행, 실패 신호는 "확인 불가"로 표기(침묵 금지)
- **데이터 시점 표기**: 모든 수치에 기준 시점 필수 (리포트 제작 시 확인된 교훈)

## 6. 성공 지표 (KPI)

- 리포트 생산 리드타임: 수동 4~5시간 → 관리자 검토 30분 이내
- 🔴 알림 정밀도(사후 관리자 판정 기준 오탐률) < 20%에서 시작, 오탐 마킹 루프로 개선
- 일일 다이제스트 발송 성공률 99%+, 고객 열람률 추적

## 7. 릴리스 단계 (권장)

- **MVP (1단계)**: F3 추적조사 단독 — 이번 리포트(8테마)의 이탈 조건을 수동으로 레지스트리에 입력하고 일일 스캔+이메일부터 가동. *리포트 자동화보다 추적이 먼저인 이유: 이미 발행된 리포트가 있고, 매일의 가치는 추적에서 나옴*
- **2단계**: F1 리포트 파이프라인 + G1/G2 게이트 + 레지스트리 자동 등록
- **3단계**: F2 정기화 + 자문사/고객 대시보드 + 오탐 개선 루프
